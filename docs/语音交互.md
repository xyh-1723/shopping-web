# 语音交互：语音输入与回复播报

购物助手（assistant 模块）现在支持两种语音能力，全部由**浏览器原生 Web Speech API** 实现，不需要后端改动、额外服务或 API 密钥：

1. **语音输入**：点麦克风说话，识别结果实时流式回填到对话框，点发送即作为普通消息交给小拾。
2. **语音播报**：开启开关后，小拾的每条回复会自动朗读；也可以点任意回复下方的「朗读」手动播报。

## 界面组件

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| 麦克风按钮 | 输入框左侧 | 点击开始/停止录音；录音中呈绿色呼吸动效 |
| 实时转写条 | 输入框上方 | 显示流式识别文本、录音计时，可随时「取消」 |
| 播报开关 | 消息区顶部工具栏 | 开启后自动朗读助手回复，偏好持久化到 localStorage |
| 音色 / 语速 / 试听 | 播报开关旁 | 选择系统中文语音包与语速，点击试听即时确认 |
| 停止朗读 | 工具栏 | 朗读过程中出现，一键打断 |
| 朗读按钮 | 每条回复下方 | 手动重播某条回复（不受总开关影响） |

## 实现结构

```text
static/js/voice.js        语音组件库（不依赖页面结构）
├── cleanText()           回复文本 → 可朗读文本：去 Markdown/链接/表情，¥ 读成「元」，超长按句截断
├── splitForSpeech()      按句切分成 ≤160 字的片段，规避 Chromium 单条 utterance 约 15 秒截断
├── SpeechInput           语音识别封装：continuous + interimResults，静音自动重启，错误码转中文提示
├── Broadcast             播报封装：分句排队、代次计数取消、音色/语速偏好持久化
└── mountVoiceUi()        把页面挂载点装配成组件，返回 { input, broadcast, halt, destroy }

static/js/assistant.js    业务接线：转写文本进输入框、回复气泡高亮朗读、发消息/切会话时停止
static/css/style.css      组件样式（呼吸灯、声波条，遵循 prefers-reduced-motion）
```

朗读与识别互不阻塞，但发送消息、切换会话、关闭页面都会先 `halt()`：停录音、停朗读，避免把话录进不存在的会话或让上一条回复继续播放。

## 浏览器兼容与常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 麦克风按钮不显示 | 当前浏览器不支持 `SpeechRecognition`（如 Firefox）。改用 Edge 或 Chrome。 |
| 提示「语音识别服务不可达」 | Chrome 的识别由远端服务完成，国内网络常失败。**Edge 使用微软的识别服务，国内可用性更好。** |
| 提示「麦克风权限被拒绝」 | 点击地址栏麦克风图标重新允许。 |
| 播报没有声音 | 系统未安装中文语音包时会退回引擎默认音色；Windows 可在「设置 → 时间和语言 → 语音」添加中文语音。 |
| 播报中途停止 | 已内置分句排队修复 Chromium 截断问题；若仍出现，多半是系统音频设备被抢占。 |

两个前置条件：

- **安全上下文**：麦克风只在 `http://localhost`、`http://127.0.0.1` 或 HTTPS 下可用。本项目默认只监听本机，因此开发场景天然满足。
- **用户手势**：浏览器要求先有交互才能发声。开关、试听、发送都是点击动作，天然满足；刷新页面后自动朗读需要先点一次页面。

## 为什么用浏览器原生 API

- 零依赖、零密钥，符合本项目「一次启动就能跑」的约定。
- 识别与合成都由浏览器/操作系统提供，中文音色质量在 Windows 上开箱即用。

## 升级路径（需要更高质量时）

当前 `Broadcast.speak(text)` 是唯一的出声入口，`SpeechInput` 是唯一的入声出口，替换实现不动业务代码：

1. **服务端 TTS**：后端接智谱 GLM、Azure 或讯飞的语音合成，新增 `/api/assistant/tts` 返回音频流，前端把 `Broadcast` 的引擎换成 `<audio>` 播放即可。优点是音色统一、不依赖访客系统语音包。
2. **服务端 ASR**：若浏览器识别不可用，可用 `MediaRecorder` 录音上传，由后端转写后回填输入框。
3. **实时打断**：接入流式回复（SSE）后，可边生成边朗读，把 `splitForSpeech` 的片段直接喂给播放队列。

## 验证方式

| 层次 | 命令 | 覆盖 |
| --- | --- | --- |
| 纯逻辑单测 | `node --test tests/voice-kit.test.cjs` | 文本清洗、分句、中间结果合并、自动重启、播报队列与取消、偏好持久化 |
| 页面渲染 | `mvn test -Dtest=VoiceUiRenderTest` | 助手页输出全部挂载点，`/js/voice.js` 匿名可访问，未登录看不到组件 |
| 浏览器验收 | `npm run test:voice:browser` | 注入假语音 API，跑通聆听 → 流式转写 → 发送 → 自动播报 → 停止 → 关闭 |

浏览器验收建议先关闭大模型，让回复内容可预期：

```shell
java -jar target/learning-mall-1.0.0.jar --server.port=8091 --mall.assistant.enabled=false "--spring.datasource.url=jdbc:h2:mem:voicesmoke;DB_CLOSE_DELAY=-1"
MALL_URL=http://127.0.0.1:8091 MALL_BROWSER_CHANNEL=msedge npm run test:voice:browser
```
