## 2026-09-28 助手安全防护 + 评测集（第二轮）
- 需求：给 assistant 加攻击防护（OWASP LLM Top 10 2025）、账号权限分级、评测集，并用真实 DeepSeek 做 UI 测试。
- 新增 assistant/security 包：InputGuard（16 类 BLOCK 规则 + 7 类 MASK，两轮扫描：清洗前/后各一次）、OutputGuard（REPLACE/REDACT/ALLOW 三级）、AssistantActor(s)（从 UserDetailsService 解析角色）、AssistantAudit（V4 迁移建表）、AssistantRateLimiter（进程内滑动窗口）、AssistantSecurityProperties。
- 权限分级：SecurityConfig 新增 admin 账号（USER+STAFF）；工具拆成 CatalogTools/CustomerTools/StaffTools，ToolRegistry 按角色下发 + 工具内 @ToolMemoryId 硬校验（memoryId 不进模型参数，无法伪造）；StaffTools 依赖 order.api 新增的 OrderInsights（stats/ordersOf）。
- AssistantService.send 重排为 限流→输入守卫→系统提示加固+<user_message> 包裹→按角色下发工具→工具循环→输出守卫→落库+审计；loadHistory 对历史用户消息重扫（防"存进历史再触发"）；新增 sendDetailed 返回 {reply, decision, notice}，旧 send() 保持兼容。
- 前端：guard-strip 角色能力条、审计面板（STAFF 可见）、guarded 气泡样式、toast 展示拦截原因。
- 评测集 tests/security-eval.cases.json（唯一数据源，Java+Node 共用）：39 防护规则 + 10 输出守卫 + 1 限流 + 10 场景；测试 AssistantGuardTest（55）、AssistantSecurityIntegrationTest（14）、tests/security-eval.cjs（端到端）。mvn verify 98/98，端到端 53/53。
- 真实模型验证：student 问 classmate 订单 → 拒绝且拿不到订单号；admin 问 → 返回真实订单数据（¥78 已支付）。
- 踩坑（都被测试抓到）：① 输出守卫误伤系统自身提示（含 DEEPSEEK_API_KEY 字样）→ 守卫只作用于模型输出；② 排版归一化被记成 REDACT 且 ruleId 为空 → 只有命中安全规则才记事件；③ jshell 配合 target/classes+cp.txt 可离线快速调规则；④ Edge/真实验证时 Playwright 抓 /messages 响应拿 decision 比读 DOM 可靠。
