# 项目长期约定（springboot-learning-mall）

## 用户已拍板的决策（2026-10-16）

### Q3 退款：做，且必须区分两类
- **无理由退款**：买家自助，无需审批。
- **需要商家确认的退款**：走商家审批。
- 因此**需要新增商家账户类型**。现有角色只有 `ROLE_USER` / `ROLE_STAFF`
  （`assistant/security/AssistantActor.java` L11-12），商家（MERCHANT）需新增。
- 不接真实资金（沿用既有"模拟支付"边界）。

### Q5 外发通道：做本地版本，但预留密钥位
- 先做**无需密钥**的本地实现（不能像视觉模型那样因缺密钥整体变死代码）。
- **必须预留密钥配置位**，方便用户后续接入真实外发（短信服务等）。
- 即：配置结构从一开始就要能容纳 `api-key` / `secret` 之类字段，只是当前不填。

### N1 + N2 一起做
- **N1**：成交后的发货 / 收货 / 完成态（PAID 目前是吸收态，没有"待发货/待收货/已完成"）。
- **N2**：退款（= P1-2）。
- 理由：没有"完成态"，退款与评价都没有落点。

### 排序参考（PM 产出，买家视角）
P1-2 退款 > P1-5 价格变动提示 > P1-1 库存流水 > P1-4 通知外发 > P1-3 可观测。
